# Глоссарий

Термины используются в сценариях, архитектуре и документах качества проекта «Разбор обращений в поддержку».

| Термин | Определение |
| --- | --- |
| Обращение | Запрос клиента и связанная с ним история обработки в рабочей системе поддержки. |
| Оператор первой линии | Сотрудник, который проверяет классификацию и черновики ответов, общается с клиентом и подтверждает передачу обращения. |
| Специалист второй линии | Сотрудник с профильной компетенцией, которому передают сложное обращение вместе с разрешённым контекстом. |
| Триаж | Первичная оценка темы, срочности и следующего шага для обращения. |
| Срочность | Приоритет обработки обращения по согласованным владельцем процесса правилам; модельное предположение не заменяет эти правила. |
| Маршрутизация | Выбор очереди или ответственного специалиста для дальнейшей работы с обращением. |
| Эскалация | Передача обращения человеку или профильной очереди, когда автоматического разбора недостаточно или требуется человеческое решение. |
| База знаний | Набор разрешённых и поддерживаемых источников, содержащих проверяемую информацию для ответа клиенту. |
| Извлечение (retrieval) | Поиск фрагментов базы знаний, релевантных конкретному обращению и доступных в его контексте. |
| Контекст | Минимальный набор сведений об обращении и найденных источниках, нужный для текущего шага обработки. |
| Черновик ответа | Предложенный системой текст, который не отправляется клиенту до проверки и явного подтверждения оператором. |
| Подтверждающий источник | Материал базы знаний, на который можно сослаться и по которому оператор может проверить утверждение черновика. |
| Структурированный выход | Результат модели в заранее заданных полях (например, тема, срочность, резюме, черновик, источники), прошедший проверку формата. |
| Граница уверенности | Условие, при котором система считает найденные свидетельства недостаточными и предлагает человеческую обработку; конкретный порог требует eval-проверки и согласования. |
| Недоверенный текст | Содержимое обращения или внешнего документа, которое может содержать ошибочные либо вредоносные инструкции и не должно менять правила системы. |
| Prompt injection | Попытка через недоверенный текст заставить модель игнорировать ограничения, раскрыть данные или выполнить неразрешённое действие. |
| Eval-набор | Версионируемый набор входов и эталонных ожидаемых результатов для измерения качества поведения системы. |
| Золотой набор (golden dataset) | Проверенная часть eval-набора с согласованными эталонами и правилами оценки. |
| ADR | Запись о значимом архитектурном решении, его контексте, выбранном варианте и последствиях, включая цену решения. |
| Цена решения | Явно названные затраты, ограничения и риски, возникающие из выбранного архитектурного варианта. |
| Human-in-the-loop | Контроль процесса человеком; в MVP оператор проверяет и подтверждает отправку ответа и передачу обращения. |
